# Roadmap

## North star

A basketball coaching sim with NBA 2K-level depth:

- **Individual player attributes _and_ tendencies.** Attributes say how good a player is;
  tendencies say how often they do things (shoot from a zone, drive, pass, post up, gamble
  for steals, crash the glass, push in transition).
- **Per-player thinking each tick.** Every player is an agent that decides from its own
  attributes, tendencies, role, and the coaching applied to it — not a single top-down
  team routine.
- **Coaching per-player and per-matchup.** Team gameplan, per-player directives ("green
  light from three", "limit his touches"), and per-matchup rules ("best defender on their
  PG", "force him left", "double on the catch", "switch all screens involving him").
- **LLM-friendly JSON player data.** A documented, versioned player schema so realistic
  rosters (NBA, college) can be generated by an LLM from public statistics and dropped in.

## Architecture principles

1. **Pure, framework-agnostic engine.** The simulation never imports UI or rendering code.
   The presentation layer (canvas court + framework UI) reads engine state and writes
   coaching back through a thin API.
2. **Seed-deterministic.** All randomness flows through a portable PRNG so games are
   reproducible and the test suite doubles as a cross-language spec.
3. **Decision separate from execution.** As player AI grows, keep "decide intent" (pure,
   per player) separate from "execute" (movement + resolution). Intents and outcomes are
   a typed event stream, which also feeds the play-by-play and enables replays.
4. **Coaching is data.** Team / per-player / per-matchup directives are JSON-serializable
   rules composed by a resolver into per-player effective parameters each possession. This
   keeps coaching LLM-generatable and replay-friendly.

## Layering (target)

```
core/ + sim/   pure engine (no DOM, no framework)
render/        Canvas 2D court (swappable; PixiJS later only if needed)
ui/            React components (coaching surface, box score, roster import)
app/           game loop + wiring; ticks engine, draws, routes UI input back in
```

## PR sequence

- **PR 1 — structure & engine (done).** Single file → TypeScript + Vite. Pure,
  seed-deterministic engine. Spec/golden test suite. Headless sim harness. Docs.
  Behavior-preserving.
- **PR 2 — React shell + player data model.** Stand up React + Vite for the UI shell.
  Define the Player JSON schema (identity + attributes + tendencies + optional traits),
  a loader, a sample roster, and the documented LLM-generation flow.
- **PR 3 — per-player decisions.** Extract the Decision layer; drive shoot/drive/pass/cut/
  screen/help choices from per-player tendencies. Team tactics become defaults/biases.
- **PR 4 — coaching system.** Per-player and per-matchup directives + a coaching resolver,
  with UI controls.
- **PR 5 — defensive matchups & assignments.** Manual and auto matchups, doubles, target
  player denial, per-matchup switching.
- **PR 6+ — depth.** Substitutions, fatigue and foul trouble, fuller transition game,
  badges/traits, set plays / playbooks.

Every system ships with tests, so the suite stays a complete cross-language spec — serving
both the "port later" and "open-source" goals.

## Player data model (PR 2 strawman)

A player is plain JSON. Sketch (to be finalized in PR 2):

```jsonc
{
  "schemaVersion": 1,
  "name": "First Last",
  "team": "home",
  "number": 7,
  "position": "SF",
  "height": 6.6,            // feet
  "attributes": {           // 25..99 ratings
    "speed": 82, "handle": 72, "pass": 66, "three": 80, "mid": 72,
    "finishing": 80, "perimD": 90, "steal": 82, "iq": 80, "strength": 74,
    "vertical": 82, "rebound": 62, "interiorD": 70, "block": 58
  },
  "tendencies": {           // 0..100 frequencies (PR 3 consumes these)
    "shootThree": 50, "shootMid": 35, "driveRim": 55, "pass": 60,
    "postUp": 10, "screen": 30, "helpDefense": 60, "gambleSteal": 40,
    "crashGlass": 45, "pushTransition": 55
  }
}
```

A JSON Schema and worked roster examples will accompany the loader so Claude Code (or any
LLM) can search public stats and emit valid rosters directly.
