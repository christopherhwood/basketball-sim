# Roadmap

## North star

A basketball coaching sim with NBA 2K-level depth:

- **Individual player attributes _and_ tendencies.** Attributes say how good a player is;
  tendencies say how often they do things (shoot from a zone, drive, pass, post up, gamble
  for steals, crash the glass, push in transition).
- **Per-player thinking each tick.** Every player is an agent that decides from its own
  attributes, tendencies, role, and the coaching applied to it — not a single top-down
  team routine.
- **Coaching per-player and per-matchup.** Team gameplan, per-player directives ("green
  light from three", "limit his touches"), and per-matchup rules ("best defender on their
  PG", "force him left", "double on the catch", "switch all screens involving him").
- **LLM-friendly JSON player data.** A documented, versioned player schema so realistic
  rosters (NBA, college) can be generated by an LLM from public statistics and dropped in.

## Architecture principles

1. **Pure, framework-agnostic engine.** The simulation never imports UI or rendering code.
   The presentation layer (canvas court + framework UI) reads engine state and writes
   coaching back through a thin API.
2. **Seed-deterministic.** All randomness flows through a portable PRNG so games are
   reproducible and the test suite doubles as a cross-language spec.
3. **Decision separate from execution.** As player AI grows, keep "decide intent" (pure,
   per player) separate from "execute" (movement + resolution). Intents and outcomes are
   a typed event stream, which also feeds the play-by-play and enables replays.
4. **Coaching is data.** Team / per-player / per-matchup directives are JSON-serializable
   rules composed by a resolver into per-player effective parameters each possession. This
   keeps coaching LLM-generatable and replay-friendly.

## Layering (target)

```
core/ + sim/   pure engine (no DOM, no framework)
render/        Canvas 2D court (swappable; PixiJS later only if needed)
ui/            React components (coaching surface, box score, roster import)
app/           game loop + wiring; ticks engine, draws, routes UI input back in
```

## PR sequence

- **PR 1 — structure & engine (done).** Single file → TypeScript + Vite. Pure,
  seed-deterministic engine. Spec/golden test suite. Headless sim harness. Docs.
  Behavior-preserving.
- **PR 2a — player data model (done).** Player JSON schema (identity + attributes +
  tendencies), an ajv-validating loader (browser via `import.meta.glob`, node via `fs`),
  sample rosters, the `generate-roster` Claude Code skill, and tests. Archetype generation
  remains the fallback when `data/` is empty.
- **PR 2b — React shell (done).** UI migrated to React + Vite (canvas court kept, engine
  untouched), with a roster/matchup selection UI over the loaded teams. React reads engine
  state via a small store + `useSyncExternalStore`.
- **PR 3 — per-player decisions (done).** Tendencies (0..100, neutral at 50) drive the
  ball-handler's shoot/drive/pass choices, off-ball cuts, screener selection, help defense,
  passing-lane gambles, offensive-glass crashing, and transition pushes — so players behave
  individually. Team tactics remain additional biases. `postUp` is defined but not yet wired
  (no post-up mechanic). Behavioral tests assert each tendency moves the box score.
- **PR 4a — balance pass (done).** Added on-ball + bad-pass turnovers/steals and lifted
  passing-lane steals, trimmed blocks, and tempered three-point volume — tuned to realistic
  ranges (TOV ~11–16, STL ~6–10, BLK ~4–6 per team/game) with a balance-floor guard test.
  Re-baselined the golden digests.
- **PR 4b — per-player coaching (done).** A `Coaching` data model (per-player directives,
  home team) + a resolver (`effectiveTendencies`) that applies coaching as additive deltas
  to a player's tendencies, swapped in at the decision sites, with a `CoachingPanel` UI (six
  instructions per player: shot freedom, shot bias, playmaking, rebounding, steals, help).
  Neutral coaching is identity, so the golden digests are unchanged. CPU is uncoached.
- **PR 5a — physical game (done).** Split `handle` into `handleLeft`/`handleRight` (default
  play uses the stronger hand; sets up weak-hand force-direction), added `weight`, wired
  `weight`+`strength` into rebounding, and added a post-up mechanic driven by the `postUp`
  tendency (strong/heavy/tall players back down a weaker defender for a close shot or foul).
  Re-baselined goldens; stats stay realistic.
- **PR 5b — per-matchup defense.** Assignment overrides, double-teams, force-direction
  (reading the weak hand), switch-all, and the matchup-grid UI (showing height/weight).
  Neutral by default.
- **PR 6 — smarter off-ball movement (done).** Role-true spacing (bigs operate inside —
  block/short-corner/dunker — shooters space the arc), the pick-and-roll screener resets
  inside instead of jogging the arc, and ball-reactive cuts (give-and-go, weak-side fill,
  backdoor) tuned to keep pace/3PA realistic. A positioning test asserts bigs play closer
  to the rim than shooters. Foundation for set plays + the rebounding rework.
- **PR 7+ — depth.** Rebounding rework (research-backed: carom + convergence + soft
  weighting), set plays / playbooks, substitutions, fatigue and foul trouble, fuller
  transition game, badges/traits.

Every system ships with tests, so the suite stays a complete cross-language spec — serving
both the "port later" and "open-source" goals.

## Player data model (PR 2 strawman)

A player is plain JSON. Sketch (to be finalized in PR 2):

```jsonc
{
  "schemaVersion": 1,
  "name": "First Last",
  "team": "home",
  "number": 7,
  "position": "SF",
  "height": 6.6,            // feet
  "attributes": {           // 25..99 ratings
    "speed": 82, "handle": 72, "pass": 66, "three": 80, "mid": 72,
    "finishing": 80, "perimD": 90, "steal": 82, "iq": 80, "strength": 74,
    "vertical": 82, "rebound": 62, "interiorD": 70, "block": 58
  },
  "tendencies": {           // 0..100 frequencies (PR 3 consumes these)
    "shootThree": 50, "shootMid": 35, "driveRim": 55, "pass": 60,
    "postUp": 10, "screen": 30, "helpDefense": 60, "gambleSteal": 40,
    "crashGlass": 45, "pushTransition": 55
  }
}
```

A JSON Schema and worked roster examples will accompany the loader so Claude Code (or any
LLM) can search public stats and emit valid rosters directly.
